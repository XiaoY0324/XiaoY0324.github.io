微前端能干什么？

微前端就是将不同的功能按照不同的维度拆分成多个子应用，通过主应用来加载这些子应用，其核心在于拆，拆完后再合，它借鉴了微服务的理念。

微前端解决什么问题

  • 不同团队（技术栈不同），同时开发一个应用
  • 每个团队开发的模块都可以独立开发，独立部署
  • 实现增量迁移

如何实现微前端

我们是不是可以将一个应用划分若干个子应用，将子应用打包成一个个模块，当路径切换时加载不同的子应用。这样每个子应用都是独立的，技术栈也不用做限制了！从而解决了前端协同开发问题。（子应用需要暴露固定的钩子 bootstrap、mount、unmount，也叫接入协议）。

  • 传统方案 iframe(通信麻烦，不保存路由状态等，具体可参考 why not iframe)、webComponent(兼容性不好，大概十几年了还没发展起来)
  • 2018 年 Single-SPA 诞生了，Single-SPA 是一个用于前端微服务化的 javascript 解决方案（本身没有处理样式隔离，js 执行隔离），实现了路由劫持和应用加载(需要 system.js)
  • 2019 年 qiankun 基于 Single-SPA，提供了更加开箱即用的 API（single-spa + sanbox + import-html-entry）做到了与技术栈无关，并且接入简单(像 iframe 一样简单)
  • 2020 年 EMP 基于 module Federation，基于 webpack5 的联邦模块，接入成本低，解决了第三方依赖包问题

SystemJS 使用和实现

SystemJS 是一个通用的模块加载器，它能在浏览器或者 NodeJS 上动态加载模块，，微前端的核心就是加载微应用，我们将应用打包成模块，在浏览器中通过 SystemJS 来加载模块。

  <script>
    let set = new Set();

    // 存储当前 window 上的属性到一个 set 里
    const saveGlobalPro = () => {
      for (let p in window) {
        set.add(p);
      }
    }

    // 如果增加了一个当前没有的属性，这个属性作为 module 传入 setter
    // 并且 module.default = module;
    const getGlobalLastPro = () => {
      let result;
      for (let p in window) {
        if (set.has(p)) continue;
        result = window[p];
        // esmodule 从 default 获取模块自身
        result.default = result;
      }
      return result
    }

    saveGlobalPro();

    // 创建 script 标签，根据全路径加载文件
    function load(id) {
      return new Promise((resolve, reject) => {
        const script = document.createElement('script');
        script.src = id;
        script.async = true;
        document.head.appendChild(script);

        // 脚本加载完成 执行 load 事件
        script.addEventListener('load', function () {
          // 当前需要加载的依赖和回调
          let _lastRegister = lastRegister;
          lastRegister = undefined; // 取完把变量情况

          if (!_lastRegister) {
            // 没有要加载的，给个空值
            resolve([[], function () { }]);
          }
          resolve(_lastRegister);
        })

      })
    }
    function SystemJS() {

    }

    SystemJS.prototype.import = function (id) {
      return new Promise((resolve, reject) => {
        // 拿到目标资源的全路径
        const lastSepIndex = window.location.href.lastIndexOf('/');
        const baseURL = location.href.slice(0, lastSepIndex + 1);

        if (id.startsWith('./')) {
          resolve(baseURL + id.slice(2))
        }
      }).then(id => {
        // 拿到路径 创建 script 标签去执行 index.js 文件
        // index.js 文件会先把依赖包加载完毕之后，再去调用 index.js 核心逻辑(execute)
        let exec;
        // 这里应该有个递归加载哦，这里没有去实现
        return load(id).then(registerition => {
          // () => { } 作为 registerition[1] 回调函数的默认参数
          let declared = registerition[1](() => { });
          // 加载 react 和 react-dom  加载完毕后调用 setters
          // 调用执行函数
          exec = declared.execute;
          return [registerition[0], declared.setters]
          // {setters:[],execute:function(){}}
        }).then((info) => {
          // info 即为 [依赖包列表，setter 列表]
          return Promise.all(info[0].map((dep, i) => {
            // 加载第几个，获取第几个的 setter 方法
            var setter = info[1][i];
            // react 和 react-dom 会给全局增添属性 window.React,window.ReactDOM
            return load(dep).then(r => {
              // 这里依赖包加载完毕 需要获取 window 最近增加的对象，作为 module，
              // 传给 setter 方法
              let p = getGlobalLastPro();
              setter(p); // 传入加载后的文件
            })
          }))
        }).then(() => {
          // exec 方法最后执行
          exec();
        })
      })
    }

    let lastRegister; // 当前需要加载的依赖模块和加载完的回调函数

    // deps 所以依赖，declareFn 定义的加载完毕要执行的回调函数
    SystemJS.prototype.register = function (deps, declareFn) {
      lastRegister = [deps, declareFn]; // 挂载到外部变量上，供外部调用
    }

    let System = new SystemJS();
    System.import('./index.js').then(() => {
      console.log('System.import 返回一个 promise');
    });
  </script>
</body>

</html>

新增 src/applications/app.js
- registerApplication 方法的实现，创建了一个应用的实例(包含状态)，并收集，然后调用 reroute 去加载应用(只在合适的场景下加载而不挂载)

code 
import { reroute } from "../navigations/reroute";
import { BOOTSTRAPPING, LOADING_SOURCE_CODE, MOUNTED, NOT_BOOTSTRAPPED, NOT_LOADED, NOT_MOUNTED, shouldBeActive, SKIP_BECAUSE_BROKEN } from "./app.helpers";

/**
 * 注册应用
 * @param {*} appName  应用名
 * @param {*} loadApp  加载的应用
 * @param {*} activeWhen 当激活时会调用 loadApp
 * @param {*} customProps 自定义属性
 */
const apps = []; // 用来存放所有的应用

// 维护应用所有的状态，状态机的概念
export function registerApplication(appName, loadApp, activeWhen, customProps) {
  apps.push({
    name: appName,
    loadApp,
    activeWhen,
    customProps,
    status: NOT_LOADED // 没被加载过
  });

  console.log(apps);
  reroute(); // 加载应用，注册应该默认会加载应用
}

export function getAppChanges() {
  const appsToUnmount = []; // 要卸载的 app
  const appsToLoad = []; // 要加载的 app
  const appsToMount = []; // 需要挂载的 app

  apps.forEach(app => {
    // 需不需要被加载，应用资源没有报错而且触发加载的条件(比如路由匹配到啦)
    const appSholdBeActive = shouldBeActive(app);

    switch (app.status) { // toLoad
      case NOT_LOADED:
      case LOADING_SOURCE_CODE: 
        // 初始化状态或者加载加载资源中，说明没有被加载，可以被加载
        // 如果命中路由，进行加载
        if (appSholdBeActive) { 
          appsToLoad.push(app);
        }
        break
      case NOT_BOOTSTRAPPED: // toMount  
      case BOOTSTRAPPING:
      case NOT_MOUNTED:
        // 以上三种状态标识没挂载过，需要被挂载
        if (appSholdBeActive) {
          appsToMount.push(app);
        }
        break;
      case MOUNTED:  // unmount
        // 在挂载着，切换子应用需要被卸载
        if (!appSholdBeActive) {
          appsToUnmount.push(app)
        }
    }
  })

  return { appsToUnmount, appsToLoad, appsToMount }
}

- 暴露核心方法 reroute
- registerApplication 时会调用该方法去 loadApps(应用加载)，实际就是调用用户传入的 loadApps 方法(返回一个 promise，且结果是个包含接入协议的对象)。
- start 时调用该方法去 performAppChanges(加载并挂载应用)，加载 => 启动 => 挂载，该方法会触发钩子函数 bootstrap、mount 的执行。

import { toBootstrapPromise } from "../lifecycles/bootstrap";
import { toLoadPromise } from "../lifecycles/load";
import { toMountPromise } from "../lifecycles/mount";
import { toUnmountPromise } from "../lifecycles/unmount";
import { started } from "../start";
import './navigator-events';

// 核心应用处理的方法
export function reroute () {
  // 获取需要被加载、挂载、卸载的应用们~
  const { appsToLoad, appsToMount, appsToUnmount } = getAppChanges();

  console.warn(appsToLoad, appsToMount, appsToUnmount);
  if (started) {
    console.log('start 方法调用 reroute');
    // app 挂载
    return performAppChanges(); // 根据路径来装载应用
  } else {
    console.log('registerApplication 方法调用 reroute');
    // app 注册，需要预先加载
    return loadApps(); // 预先加载应用
  }

  // 应用的加载，其实就是执行传入的加载函数(该方法必须返回 promise)，拿到返回的 bootstrap, mount. unmount
  // 放到 app 上！
  async function loadApps() {
    // 获取到每个应该被加载的应用的接入协议
    let apps = await Promise.all(appsToLoad.map(toLoadPromise));

    console.error(apps);
  }

  // 应用 start(挂载)
  async function performAppChanges() {
    // 先卸载不需要的应用，没写 promise.all 和 await，表示并发卸载
    let unmountPromises = appsToUnmount.map(toUnmountPromise);

    // 未加载未挂载在这里
    // 去加载需要的应用，将需要去加载的应用拿到 => 加载 => 启动 => 挂载
    // 这个应用如果未加载过，需要在这里进行加载
    appsToLoad.map(async (app)=>{ 
      app = await toLoadPromise(app); // 加载应用
      app = await toBootstrapPromise(app); // 启动应用

      return toMountPromise(app); // 挂载应用
    })

    // 注册时已加载未挂载的，在这里处理，不用再次加载 
    appsToMount.map(async (app)=>{
      app = await toBootstrapPromise(app);
      return toMountPromise(app);
    });
  }
}

新增加载应用的方法 src/lifecycles/load.js>

- 提供应用加载的方法 toLoadPromise，会缓存应用加载的状态(保证同一时期一个应用只有一个异步加载任务)，然后执行用户传入的加载应用方法，拿到接入协议，并拍平重组为一个函数作为协议的值(针对接入协议可能是数组的情况)。

code 
import { LOADING_SOURCE_CODE, NOT_BOOTSTRAPPED } from "../applications/app.helpers";

function flattenFnArray(fns) {
    fns = Array.isArray(fns) ? fns : [fns];
    // 通过 promise 链来链式调用，多个方法组合成一个方法，pre 传入默认值 Promise.resolve()
    // 最后组合成了一个会依次等待执行的大的函数
    return (props) => fns.reduce((pre, next) => pre.then(() => next(props)), Promise.resolve());
}


export async function toLoadPromise(app) {
    // 防止加载 app 的方法重复调用，注册一次，同步 start 又一次，
    // 然后才执行到异步加载更改状态，所以在这里加个锁，只触发一次异步加载
    if (app.loadPromise) {
        return app.loadPromise;
    }

    // 把 app.loadPromise 存起来了，用于第二次执行时的判断
    return (app.loadPromise = Promise.resolve().then(async () => {
        app.status = LOADING_SOURCE_CODE; // 正在加载资源
        // 调用用户传入的加载应用的方法，传入自定义的 props
        let { bootstrap, mount, unmount } = await app.loadApp(app.customProps);
        app.status = NOT_BOOTSTRAPPED; // 没有调用bootstrap方法

        // 把协议挂载到子模块实例上，并且拍平用户传入的协议方法，这些方法可能为数组
        // 我希望将多个promise组合在一起 compose
        app.bootstrap = flattenFnArray(bootstrap);
        app.mount = flattenFnArray(mount);
        app.unmount = flattenFnArray(unmount);
        delete app.loadPromise; // 加载完了干掉 loadPromise
        return app;
    }))
}

js 沙箱方案

如果我在 A 应用中赋值 window.a = 1，那么 B 应用的 window 也会存在 a，污染全局变量 window 这不河里！我希望应用有自己干净的全局变量，比如切换到 B 时，变量 a 从 window 上丢弃，而切换回 A 时，我可以选择丢弃属性和恢复属性。

js 沙箱分为两类：快照沙箱(兜底)和 proxy 代理沙箱

快照沙箱

  1. 沙箱实例储存 window, 使用 map 结构记录修改属性。
  2. 应用激活时，给当前初始 window 拍个照，并且从记录修改属性的 map 中恢复属性到 window。
  3. 应用失活时，拿当前的 window 和先前保存的 window 快照比对，把修改的属性保存到 map 中，并把 window 从快照中还原。
class SnapshotSandbox {
  constructor() {
    this.proxy = window; 
    this.modifyPropsMap = {}; // 修改了那些属性
    this.active();
  }
  active() {
    this.windowSnapshot = {}; // 给 window 拍个照~

    for (const prop in window) {
      if (window.hasOwnProperty(prop)) {
          // 将 window 上的属性进行拍照
          this.windowSnapshot[prop] = window[prop];
      }
    }
    // 从存储的修改属性 map 中把之前操作过的 window 属性还原
    Object.keys(this.modifyPropsMap).forEach(p => {
      window[p] = this.modifyPropsMap[p];
    });
  }
  inactive() {
    for (const prop in window) { // diff 差异
      if (window.hasOwnProperty(prop)) {
        // 将上次拍照的结果和本次 window 属性做对比
        if (window[prop] !== this.windowSnapshot[prop]) {
            // 保存修改后的结果
            this.modifyPropsMap[prop] = window[prop]; 
            // 还原 window
            window[prop] = this.windowSnapshot[prop]; 
        }
      }
    }
  }
}

proxy 沙箱

每个应用都创建一个 proxy 对象来代理 window，好处是每个应用都是相对独立，不需要直接更改全局 window 属性！

class ProxySandbox {
  constructor() {
    const rawWindow = window;
    const fakeWindow = {}; // 每个应用一个对象，存储自己的东西~

    const proxy = new Proxy(fakeWindow, {
      set(target, p, value) {
          target[p] = value;
          return true
      },
      get(target, p) {
          return target[p] || rawWindow[p];
      }
    });

    this.proxy = proxy // proxy 是代理后的对象，我们把它作为 window 传入子模块
  }
}

模块联邦使用

为什么会有模块联邦(module federated)

webpack5 引入联邦模式是为了更好的共享代码。 在此之前，我们共享代码一般用npm发包来解决。 npm发包需要经历构建，发布，引用三阶段，而联邦模块可以直接引用其他应用代码,实现热插拔效果。对比 npm 的方式更加简洁、快速、方便，且分开构建，构建性能会好很多(快)。

容器和远程模块的概念

*. 每一部分被单独构建，且这些部分都称为容器，如果容器 A 使用了容器 B，那么相对 A 来说，A 被称为主机，B 被称为远程模块
*. 如果 B 容器引入了 C 容器，B 本身是也是个主机，C 被称为远程模块
